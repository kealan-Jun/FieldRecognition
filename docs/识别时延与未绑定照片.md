# 语音照片识别与时延留存

本机后台监控配置相机的 NAS 语音照片。没有有效绑定也执行 OCR、按规则尝试视觉兜底，并保存原件和过程回执。二维码绑定用于关联仪器，不再是照片识别的前置条件。

## 照片与身份

- `FIELD_CAMERA_ID` 指定监控相机；只读 `voice_photos/<camera_id>/日期/时间/照片`，不扫描其他相机或录像目录。
- 自动导入时，有仍有效且开始时间不晚于拍照时间的绑定才尝试关联。绑定已失效、照片更早或已解出的二维码与绑定冲突，照片仍按未绑定任务识别。
- 未绑定任务的 `binding_id`、`instrument`、`scene`、`scene_visit_id` 为 null，`instrument_association=unbound_photo`，`scene_qr_verified=false`。不从面板文字或登记库猜身份，也不把后来创建的绑定补到旧照片上。
- 拍摄时已有相机实验员登记，才保存该登记的姓名、时间和 `operator_basis=camera_registration`；缺失时保持 null。绑定任务另保留当时的绑定快照。
- 自动语音照片任务提交后，即使设备离线或绑定结束，也继续处理已保存照片。显式传入 `binding_id` 的手动请求仍执行绑定校验，发生冲突时拒绝，避免把结果挂错仪器。

首次监控窗口从已有实验员登记时间开始；没有登记时从首次启用监控的时间开始。`photo_watch_windows` 按相机保存此窗口，重启、换人或重新绑定不会清除它。只补处理窗口内尚未导入的照片。早于窗口的照片可通过确切路径显式提交；不能推断当时的操作人。

文件签名与处理状态保存在 `photo_watch_files`；旧 `photo_watch_seen` 继续用于历史去重。导入使用相机、源照片编号及 SHA-256 校验，OCR 使用导入照片和选框去重。同一文件重传、重新绑定、重启不会自动生成重复读数任务或重复付费；原有失败/中断结果也保留。

## 接近实时的执行方式

监控每轮结束后等待 **0.5 秒**，大小和修改时间保持 **至少 0.5 秒** 才读取；读取前后再次比较文件状态。启用照片监控时，服务启动即在后台预加载 GPU OCR；后续照片复用同一实例。

无队列、NAS 通畅且模型已就绪时，目标是文件写完后约 1 秒开始识别。这个目标不是已测得的服务保证：SMB 缓存、目录扫描、图像导入、文件写入速度和任务积压都会增加等待。当前每轮最多导入一张、全局最多四个排队/运行任务，四个调度线程分别计时，OCR 单线程复用模型；一次语音操作产生三张照片时，一张的兜底等待不会占住其他调度线程，各张仍保留独立证据。

本地完整数字候选可立即返回。单张任务实际开始运行 **5 秒** 仍无完整数字时才尝试视觉模型，所以兜底路径至少包含这五秒与网络推理时间；排队时间另计。每张任务最多一次云端请求，同一绑定、或未绑定时同一相机，两次尝试至少间隔 30 秒。间隔内记录 `fallback.status=skipped`、`reason=cooldown`，不称作已调用模型。视觉请求的并发上限仍为一个；槽位占用时记录 `reason=busy`，直接保留本地结果，不提前扣占冷却时间，也不自动重复请求。

文件首次被发现时距离其 mtime 已超过 30 秒，标为 `timing.is_backfill=true`。这是保守的延迟/补处理标记，不是证明此前服务停机。页面对这类任务显示“补处理 · 发现至结果”，原始写入时间和全部差值仍保留在 JSON。

## 时间字段

`GET /api/jobs/{job_id}`、Agent `get_panel_result` 和 NAS 任务回执的 `document.timing` 保存以下字段。未发生或不能测量的阶段不填造时间，差值为 null。

| 字段 | 含义 |
|---|---|
| `source_written_at` | NAS 文件最终被读取时的 mtime；结构化 Agent 输入可提供声明的写入时间 |
| `source_written_basis` | `nas_file_mtime`、`agent_receipt` 或 `not_recorded` |
| `first_observed_at` | 监控首次看到当前文件签名的本机 UTC 时间，队列满时仍发现文件 |
| `stable_at` | 当前签名满足稳定等待的首次观察时间 |
| `read_started_at`、`photo_read_at` | 开始读取源文件、完成源照片读取及路径校验 |
| `imported_at` | 本地图片校验、保存、照片内二维码解码完成后的时间 |
| `queued_at`、`run_started_at` | 读数任务提交和实际开始运行时间 |
| `ocr_started_at`、`ocr_finished_at` | OCR 工作线程实际开始预测至结束；冷启动时可能包含模型加载 |
| `vision_started_at`、`vision_finished_at` | 视觉兜底调用开始与返回，包括明确的请求失败 |
| `result_generation_started_at`、`result_generated_at` | 从生成规范读数、测量记录和展示字段到生成完成 |
| `result_finished_at` | 最终任务结果保存前的本机 UTC 时间 |
| `archive_published_at` | 不可变回执发布完成；由归档数据库在查询时提供 |
| `archive_readable_at` | 归档写入端完成包含该版本的派生 Evidence/Result 视图发布；不是客户端首次读取时间 |

`timing.durations_ms` 单位为毫秒，包含 `write_to_detect_ms`、`file_stability_ms`、`ingest_wait_ms`、`file_read_ms`、`import_ms`、`queue_wait_ms`、`ocr_wait_ms`、`ocr_ms`、`vision_ms`、`write_to_ocr_ms`、`write_to_result_ms`、`detect_to_result_ms`。

新增 `result_generation_ms`（规范结果生成）、`result_finalize_ms`（生成完成到结果保存前）、`write_to_readable_result_ms`（源文件写入到派生视图发布）、`archive_publication_ms`（任务结果完成到不可变回执发布）和 `archive_readability_ms`（不可变回执发布到派生视图发布）。`panel_detection_ms` 单列面板检测，`processing_ms` 汇总任务运行到结果完成。无法重建的历史阶段时间保持 null，不把旧视图重建时间填成当年的首次可读时间。

NAS mtime 是文件系统时间，**不等于上游程序的原子写入完成回执**；NAS 与本机时钟尚未独立校准。`source_clock_basis` 明示依据，负的写入差值保留为 null，并用 `source_clock_ahead` 标记。`external_photo.captured_at` 仍是文件名或 Agent 声明的拍摄时间，不用于冒充写入时间。

归档成功在文件发布后确认。任务查询的 `archive` 提供 `status`、`queued_at`、`archived_at`、`receipt_path`、`archive_queue_ms`、`write_to_archive_ms`；NAS 的 `Index.json` 同样记录归档确认时间和时延。不可变回执保留提交时的快照，确认信息由后续索引/数据库提供，不回写旧回执。

`archive` 另提供 `published_at`、`readable_at` 和 `readability_basis=archive_writer_derived_views_published`；其 `archive_publication_ms` 从该版本归档排队时间起算，区别于 `timing.durations_ms` 中从任务完成起算的同名字段。派生 Evidence 的每项 observation 在读取归档行时合并该任务版本的时间。跳过识别的事件仍可发布 Evidence，`archive_readable_at` 不承诺存在 Result.json。客户端验收应独立记录 t0、Evidence 与各 Result 的首次成功读取时间，保留轮询间隔、时钟依据和跳过原因。
