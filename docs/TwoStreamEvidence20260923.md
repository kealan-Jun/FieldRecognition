# 视频自动留证与语音三连拍：同一采集时间轴

业务只采用两条采集线：视频 OCR 自动留证，以及外部语音拍照系统写入 NAS 的三连拍。
FieldRecognition 不负责触发外部拍照、不修改源照片、不要求在网页手动上传。
旧上传接口和历史 PhotoReadings 材料继续兼容，工作台不再把上传列为主要采集操作。

## 视频：无需等待语音指令

已绑定设备的读数稳定且变化时保留完整帧、区域与结果。读数保持不变时，
也定期保存新帧，默认每 30 秒；使用 `FIELD_VIDEO_EVIDENCE_INTERVAL_SECONDS` 调整，
允许 2–3600 秒。每次仍需当下画面的稳定识别，不从上一条读数复制出新的观测。
支持帧标识与文本保留在 temporal_confirmation，保存的是当次代表帧。

`video_observation.evidence_reason` 区分 `reading_changed`、`reading_periodic`、
`unreadable_timeout`。时间来源、帧序号、图片 SHA-256、当时绑定和原始 OCR 继续保留。
生产模式的新视频任务标记 `record_scope=field_observation`；不会自动变成正式确认记录，
也不创建语音照片草稿。历史 test_only 标记不回写。

抽帧上限仍为 2 帧/秒；已入队照片优先，队列满时不强行抢占。
定期间隔是满足新鲜画面、稳定识别及资源条件后的保存策略，不是固定时延保证。
不保存普通背景帧，不将两次观测之间的数值推定为恒定。
定期留证会比只保存变化增加图片与回执数量；原有图片哈希去重和容量不足时保留本地队列的策略继续生效。

## NAS 接收端的三连拍归组

源目录仍为 `voice_photos/<camera>/<date>/<time>/<photo>`。相机按目录隔离，
每张照片保留原有来源、拍摄时间和字节哈希。一个明确批次共用 measurement_id，
同时保留三个 capture_id、三个 job_id 和逐张候选。

默认 `FIELD_VOICE_PHOTO_BATCH_MODE=receipt_only`，沿用现有 PhotoReceipt.json 协议。
无回执的照片继续识别和留证，但时间追溯页明确显示“批次关联未确认”，
不把文件后缀或同秒时间当作可靠连拍关系。

若已核对外部来源遵守“一个拍照目录就是一次语音指令，目录内固定三张照片”，
可在下一次允许的部署中选择 `FIELD_VOICE_PHOTO_BATCH_MODE=directory_triplet`：

- 归组由本项目的只读接收端完成，外部拍照程序无需更改。
- 目录不足三张时保留持久化导入队列，等待补齐；超过三张则报告边界不明确。
- 检查全部三张照片的相机、文件名时间、文件稳定性和哈希；读取期间发生变化会重试。
- 批次 ID 由带相机的源目录和协议版本确定，不使用当前用户、当前绑定或识别值生成。
- 在本地采集回执保存三张清单，明确 `batch_basis=configured_directory_triplet`。
  不在源 NAS 写入 PhotoReceipt.json，不冒充采集端出具的回执。
- 图片时间仍标记 `nas_filename_local_time_not_hardware_verified`。归组不提升时钟证据等级。
- 已导入照片与新批次声明不一致时拒绝重新归组，保留旧测量、旧任务和绑定。
- NAS 中已有真正的 PhotoReceipt.json 时优先验证它；损坏回执不降级绕过。

2026-09-23 NAS 维护期间曾因读取超时暂停现场核对。恢复后，两个已配置相机的真实目录
均通过接收端三张清单、路径、时间及哈希校验；结合用户说明的语音三连拍流程，
本机在本次授权停服部署时启用 directory_triplet。历史缺张目录保持原状，未来缺张等待补齐。
这属于接收端配置的来源约定，不是采集端签发的批次证明，也不证明设备时钟同步。

## 按采集时间查两条线

新增 `/trace` 页面和只读 `GET /api/evidence-timeline`，也提供同规则的 `/api/v1/` 别名。

参数：`camera_id`（或 X-Camera-Id）、带时区的 `start` 与 `end`、
`stream=all|video|voice`、可选 instrument_id / wearer_id、limit（1–100）、offset。
时间区间为 `[start,end)`，最多 31 天，按 UTC 归一后的采集时间升序。
例如用同一北京时间区间查看两条线：

```text
GET /api/evidence-timeline?camera_id=Camera01&start=2026-09-23T10%3A00%3A00%2B08%3A00&end=2026-09-23T10%3A05%3A00%2B08%3A00
```

页面明确显示北京时间；每张图片可以打开原始图像、任务和识别版本回执。
支持导出当前页 JSON。自动结果、草稿、失败和未读清的材料均可追溯，
不以正式确认或“有数字”作为保留证据的前提。

每次查询在同一数据库读事务内取得快照，不修改运行数据。只读事务仍可能在非 WAL
环境短暂等待写入；部署使用项目既有 SQLite 配置。分页查询以各次读取时的状态为准。
当前按所选相机读取历史任务后筛选；大规模历史需要后续持久化时间索引优化。

时间依据分为同步视频帧时间、来源回执声明时间、NAS 文件名时间、未知。
没有有效采集时间的事件单独计数，不拿 submitted_at、received_at 或处理结束时间补齐。
该未知计数覆盖所选相机、来源和身份的全部历史，无法断言属于本次时间范围。
时钟精度或偏移未知时 uncertainty_ms 为 null；相同物理时间不等于设备时钟已校准。
不按“距离最近”自动把视频和语音事件合并，也不把没有语音照片直接判为实验员漏报。

连拍任一成员落在查询区间内，就展示该批次全部已有成员并逐张标出时间。
重识别使用最新已完成版本；进行中或失败的重识别不会遮盖前次已完成证据，
旧版本继续通过 versions 链接读取。不同相机与使用时段不会因时间接近而合并。

## 证据边界

- PROVEN：临时数据下的两路时区排序、未知时间排除、照片归组、重复提交去重、
  历史归属保留、逐张照片及归档回执完整性。
- PARTIAL_EVIDENCE：上线后服务身份、启动配置、GPU 常驻状态、真实历史时间轴查询、
  NAS 有限读写与哈希抽查，以及两个真实目录的接收端三张清单校验。
- NOT_PROVEN：现场新一次语音指令到三张归组及归档的完整验收、停电/整机重启、
  连续扫码无损升级和真实仪器 OCR 准确率。部署时相机上游离线，未验证新视频读数留证。
