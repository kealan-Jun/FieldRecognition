# 自动解绑与重新扫码（2026-09-21）

一台相机可以绑定多台仪器，多台相机可以共享同一场景。仪器在有效使用时段内独占；原相机离线或采集服务异常后自动释放，其他相机通过实际扫码即可绑定。此流程不要求网页申请、交出或接收确认。

| 观测事件 | 绑定处理 |
|---|---|
| Receiver 报告设备状态或媒体服务离线 | 结束该相机的仪器和场景绑定 |
| 相机不在 Receiver 列表、状态过期、接口超时或不可用 | 以服务异常原因结束该相机绑定 |
| 主码流读取或解码失败、连续超过 8 秒没有解码画面、扫码服务异常 | 结束当前采集会话与绑定 |
| RGB 接入会话或明确的设备开机标识变化 | 结束旧会话，等待新扫码 |
| 本项目相机采集进程退出、重启或停止响应 | 结束该相机绑定；监督进程负责处理无法自行清理的退出 |
| 北京时间跨日 | 旧绑定结束时间记为零点，次日重新扫码 |

解绑基于检测到的状态，不把检测时间当成可证明的物理断电时间。正常状态轮询间隔为 1 秒，Receiver 状态接口超时为 5 秒，主码流读取超时为 8 秒。画面超过 1 秒不再用于扫码，页面显示等待新画面；连续超过 8 秒无解码画面才按画面中断解绑，启动后始终没有首帧也适用。明确离线、读取或解码报错仍立即结束绑定。采集失败后，只有在线状态与实际新解码画面同时恢复才恢复扫码，单独心跳不能反复恢复会话。进程退出由每 2 秒运行的监督循环发现；无响应沿用 120 秒心跳看门狗。相机重新上线时再次作废旧凭证，包括离线期间保存的扫码，只有恢复后新解码的画面可用于绑定。

关闭网页不会停止后台采集。照片/OCR/NAS任务的单独失败不作为设备关机；已采集照片继续按原拍摄时段处理。采集服务重启（含部署重启）会结束原会话。

历史绑定不删除，保留扫码 ID、原图、开始时间、人员和仪器/场景身份，追加 `ended_at`、`end_reason`、观测信息及 `session_lifecycle_policy=camera-service-session/1`。解绑与释放占用在同一数据库事务完成，只影响发生异常的相机。未完成的旧交接预约若涉及该相机也会失效，避免预约继续占用已释放仪器；旧接口和历史回执继续保留兼容。

NAS 沿用既有 `日期_相机/Bindings/事件/Binding.json`，结束记录更新状态并追加不可覆盖回执；新相机绑定创建自己的记录，不覆盖原相机历史。

验证边界：自动回归用真实 QR 解码和临时数据库验证离线释放、多仪器追加、另一相机无网页交接直接绑定、旧凭证拒绝、恢复后新扫码、北京跨日、服务状态异常、进程异常及 NAS 结束记录。它们不替代物理设备断电/再次开机的现场验收，也不证明 OCR 实测准确率。
