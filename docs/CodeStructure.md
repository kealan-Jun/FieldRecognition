# 代码结构与维护

代码按职责组织在 `field_recognition/`。仓库根目录只保留服务和客户端的兼容入口，现有 systemd 模板及 `uvicorn app:app`、`python -m ocr_worker` 等启动命令仍可使用。

整理参考了 [FastAPI 的多模块应用说明](https://fastapi.tiangolo.com/tutorial/bigger-applications/) 与 [Requests 的仓库布局](https://github.com/psf/requests)：源码归入包，测试和文档有独立入口，再按本项目业务边界拆分。原先根目录的 80 个 Python 模块归入包，根目录保留 12 个有实际启动或导入用途的兼容入口。

| 目录 | 职责与边界 |
| --- | --- |
| `api` | 应用工厂、请求模型、HTTP 路由、Agent 工具；调用业务动作，不复制事务 |
| `bindings` | 身份独占、使用时段、采集会话校验、明确交接 |
| `capture` | Receiver、二维码解码、实时扫码、已保存照片导入与观察 |
| `recognition` | 模型生命周期、面板/数字区域处理、本地与远程识别流程 |
| `measurements` | 公共读数语法与单位、候选校验、连拍草稿、确认事务、时间依据 |
| `archive` | 事务 outbox、不可变证据、事件发布、索引与可读性 |
| `runtime` | 显式上下文、配置、数据库、队列、IPC 与独立 worker |

模块导入不启动应用。工厂显式创建运行上下文和服务，进程从同一份配置快照取得参数。旧组件的 `core[...]` 接口通过映射适配器连接上下文；根 `app.py` 保留可被测试替换的兼容属性。新代码直接使用工厂和上下文。

数据库、进程锁与 IPC socket 使用同一个实例数据目录；环境变化不会把代理连到另一个实例。应用和 worker 在启动失败或退出时统一回收资源，关闭已加载的远程客户端不会触发模型加载。GPU 验证工具使用显式临时配置，不继承生产数据库、相机、归档或远程识别来源。

测量修订/确认与交接请求/决策分别由业务动作实现。HTTP 和 Agent 调用相同方法，继续执行角色、相机、版本、二维码身份和原图哈希检查。事务提交后的确认回执保持幂等，旧证据不自动升级为新结果。

公共数字语法和单位在 `measurements/readout_rules.py`；视觉配置统一解析，未读到数字的等待阈值支持有限浮点数 `0.1–120` 秒，默认 `5.0` 秒。无效环境值使用同一默认值，显式配置对象拒绝越界值。前端 `static/view-utils.js` 统一 HTML 转义、北京时间和状态显示，工作台控制器通过显式页面上下文协作。

`runtime/paths.py` 定义项目资源根目录和源码指纹解析。移动模块不会把 `Data/`、注册表或 `static/` 的默认位置改到包内。历史回执里的旧文件名作为键保留，新回执哈希来自实际实现文件；旧回执不改写。离线归档页面内联所需展示脚本，仍可独立打开。

测试按业务分目录，公共夹具和模型/相机替身集中在 `tests/support/`。测试模块不互相导入。测试临时目录使用短名字，避免 Unix socket 的路径长度限制。完整验证命令见 [Agent 指南](../AGENTS.md)。

Python 格式统一使用 Ruff，静态检查关注未定义名字；JavaScript、HTML 与 CSS 保持可读格式。提交时运行全部 JavaScript 语法检查和适当的行为回归，避免只校验主入口。依赖版本继续由 CPU/GPU 锁文件控制，重构不要求升级生产环境。

本轮整理须在独立工作区验证，推送提交与实际运行部署分别记录。升级检查仍由 `scripts/upgrade_runtime.py --revision <SHA>` 执行；没有经验证的不中断替换路径时，运行代码保持待部署。
