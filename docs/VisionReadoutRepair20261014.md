# 云端读数协议：多区域数字与 OFF 状态

`panel-readout-v3-display-states` 将数字和明确的 OFF 分开传递。旧协议只接受数字，原始回答即使读出 OFF，也不能形成有效状态；部分模型还把两个显示区域的数字拼在一个条目中，导致数字与原文的一致性校验失败。

数字仍在 `answer.readings[]` 中，每个条目的 `text`、`value` 对应一个显示区域。数字语法、正负号、小数点及完整转录校验保持不变，不从失败回答中拆猜数字。提示词明确要求同台仪器左右、上下的显示区域也分别转录。

OFF 使用独立数组，例如：

```json
{
  "status": "readable",
  "readings": [],
  "display_states": [{"text": "OFF", "state": "OFF", "label": null}],
  "notes": ""
}
```

每个状态项必须有独立的完整 OFF 原文；`0FF`、`OFF OFF`、数字或附加 `value=0` 均被拒绝。旧数字回答省略 `display_states` 时按空数组兼容。只有数字和状态都为空时才允许 `unreadable`。

转换后的 `lines[]` 保留 `display_state=OFF`、`value=null` 和空 `numeric_candidates`，不会应用固定小数规则。无绑定或全图恢复结果仍是未归属证据，不产生仪器绑定或正式测量记录。

已有定位和任务绑定快照确认字段时，只有单个 OFF、没有数字冲突、标签不冲突且不存在原生笔画/方向拒绝证据，才把 OFF 传到该字段的 `panel_regions[].display_state`。多区域、字段角色缺失或冲突回答保留在原始云端回执中，不升级为该字段的状态。已有六字段记录和归档契约的 `value=null, display_state=OFF` 保持不变；所有模型结果仍未经人工确认。

## 验证与部署边界

隔离回归覆盖接口状态校验、数字兼容、无绑定 OFF、定位字段 OFF、混合数字/状态冲突、重复状态及原生拒绝证据。完整测试通过 1147 项，保留两条已有依赖弃用警告。

真实照片对照沿用之前冻结的 160 个输入与参考，不按预测结果删除图片，不更改数字解析，不重试或择优。搅拌器数字和 OFF 仅比较转录匹配，不证明字段角色与仪器身份；旧接口的 OFF 分数结构上为零，不能用前后分数解释模型本身能力的变化。搅拌器和整图天平参考尚未经人工真值确认，真实现场准确率仍为 `NOT_PROVEN`。
