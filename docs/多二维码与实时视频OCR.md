# 多二维码、实时视频 OCR 与实验台分类

本说明对应 2026-09-14 新增实现。替代原来“相机只能绑定一个仪器、绑定后停止扫码、视频不执行 OCR”的限制。

## 关联生命周期

同一个相机、实验员和设备采集会话，可以同时保留场景、仪器 A、仪器 B 的关联。场景和每台仪器也可以独立扫码，不要求按顺序扫描。单帧实际解出多个已登记二维码时逐项建立关联；未登记码不提供身份，也不会阻止同帧其他有效码处理。仪器仍须先填写登记场景。

`bindings` 每个仪器一条；`scene_visits` 每个场景一条。事务检查同相机、仪器的现存有效关联，同一人员重复提交返回原 ID，不改开始时间；当天内提交新操作人可直接更新，保留绑定 ID、有效期、二维码哈希及原扫码照片，追加 `operator_history` 并归档为新的不可变版本。场景重复进入同样支持换人。迟到照片按拍摄时间还原当时的操作人。持续扫码只为尚未关联的码保存命中帧和建立关系，已有码不会每帧落盘或反复绑定；更换全相机当前使用人通过登记或自动运行设置完成。一个码失败不撤销同帧其他码已成功的关系，错误独立保留。

设备离线或 Receiver 的采集会话标识变化，会结束该相机的全部有效关联；重新上线需要新画面扫码。本机识别服务重启时，上游采集会话未变则保留关联，不为网页刷新重复绑定。网页“结束本轮全部关联”结束仪器和场景关系并暂停自动扫码。

## 两条 OCR 输入

- 语音照片：保持原来 NAS 0.5 秒轮询、至少 0.5 秒稳定性检查，逐个文件去重、识别和留存。
- 实时视频：`video_ocr.py` 每 0.5 秒尝试取一张新鲜帧，复用常驻 PaddleOCR 的单线程 GPU 工作队列。最多一个视频推理在途，语音照片及其他已排队任务优先；忙时跳过采样，不积压视频帧。实际频率取决于图像复杂度和 GPU 耗时，上限为 2 帧/秒，不保证处理所有 30fps 输入帧。

视频推理结果先保存在内存，通过 `/api/video-ocr` 供页面每 0.5 秒查询。页面分开显示实时数字候选和最近保存的识别结果。模型常驻与正在推理的状态分别展示。视频识别可独立暂停、恢复，设置持久化到本机数据库；语音照片监控不随之关闭。

## 视频证据留存

普通视频帧不写入本项目存储。相同数字候选连续两次出现、与上次保存的数字或实际解码仪器身份不同，并且距上次留存至少 2 秒时，保存这一帧。多台仪器显示相同数字时，实际解出的不同二维码身份会产生不同事件。没有二维码时保留本次会话的候选仪器集合，不把它当作实际入镜身份。

无数字且无仪器码的背景帧只在内存处理，不保存、不创建任务、不调用云端。实际解出仪器码但连续 5 秒没有完整数字，或数字小数点可疑时，保留受控异常证据；相同异常身份不周期重复存图，不同异常证据间隔至少 30 秒，使用既有视觉兜底机制。只有新鲜帧参与推理；相机离线、旧会话或超过 3 秒的延迟推理结果不用于新证据。语音照片到达优先，因而视频显示可能短暂提示“优先处理语音照片”。

证据写入 `scans` 与 `jobs`，带 `request_trigger=video_stream`、`video_observation`、相机帧序号和时间。复用刚完成的本地 OCR 结果，不为落盘再调用一次 OCR。已有归档队列继续把原图、结果版本和索引同步到独立 NAS 目录。

## 多读数与归属

一张照片只创建一个任务，可包含多个 `readings`；每个数字区域有独立 `reading_id`、原文、数值字符串、单位、OCR 多边形、候选仪器、原图和任务引用。数组中的区域不等于已可靠检测到物理显示屏，当前全文 OCR 仍可能读到背景数字。

`binding_snapshots`、`binding_ids` 保存照片时可用的关系。照片实际解出的仪器码用于缩小候选集合；明确只有一个候选时可关联该仪器，并保留 `association_basis`。多个候选时单值 `binding_id` 和 `instrument` 为空，各读数保留候选数组，显示待归属；不能按数据库第一条绑定、标签文字或空间距离猜测。显式单仪器选框接口仍兼容。照片实际解出唯一已登记仪器码时，即使没有有效会话绑定，也直接使用登记身份归类；`instrument_identity_basis=decoded_photo_qr`，`binding_id` 仍为空，不补造绑定记录。仪器身份确定和面板读数准确率分别保留证据边界。

**边界：** 某张图只解出一个仪器码，不代表图中全部背景数字都来自这台仪器。候选归属不是已验证的测量真值；多屏自动定位、二维码与物理面板的可靠对应仍需要标注校准或专用定位算法。所有结果保持 `human_verified=false`、`activity_confirmed=false`，不根据读数声称发生了称量等物理操作。

小数点疑似缺失（如 `00000`）保留原文并标记 `decimal_uncertain`，不会自行补成 `0.0000`。视觉接口返回多条读数，一块面板不可读时不要求丢掉其他可读结果。全图其他数字存在仍可能阻止无数字兜底；尚未实现每个物理面板各自的独立超时。

## 实验台 → 仪器 → 读数

任务和各读数包含 `workbench` / `workbenches`。A、B 登记于同一实验台时汇总到同一个实验台；实际场景扫码证据与登记位置仍以 `basis` 区分。跨实验台且无法确定时不挑选其中一个。

`GET /api/workbenches?limit=200` 返回最近 200 个任务的分类视图（允许 1–500），包含每台仪器的读数列表、实验台待归属列表、识别次数和读数条数。页面“操作记录 → 按实验台与仪器分类”提供实验台总览，每组展示最近 8 条，完整任务在“全部读数”分页查看。统计是记录数量，不把 A/B 的测量值相加。

NAS `Index.json` 新增 `reading_regions`、`binding_ids`、`workbench`、`workbenches`、`input_mode`，保留现有 schema/2 向后兼容。全量索引可按实验台或仪器筛选；原始历史回执不重写。旧记录分类来自当时保存的绑定快照，不补造新的二维码证据。

## 新增接口与配置

| 接口 / 配置 | 用途 |
|---|---|
| `FIELD_VIDEO_OCR_ENABLED=1` | 首次启用视频识别；界面保存的启停设置优先 |
| `GET /api/video-ocr` | 实时状态、已推理帧数、最新候选、证据计数 |
| `PUT /api/video-ocr`，`{"enabled":true}` | 持久化启停，关闭网页继续运行 |
| `POST /api/camera/relations/end`，`{"camera_id":"..."}` | 结束指定相机本轮全部仪器和场景关系 |
| `GET /api/workbenches` | 实验台、仪器和待归属读数分类 |
| `POST /api/ocr`，`auto_associate=true` | 按该图二维码和可用会话关系解析候选 |

九个原有 Agent 工具保持兼容；自动实时视频识别无需修改 Agent 拍照服务。视频时延以本机观察帧到结果计时，新增 `frame_to_result_ms`；语音照片仍保留写入到发现、识别、归档的分段时间。

## 验证边界

自动测试使用真实二维码解码和 OCR/网络替身，覆盖三个码同帧、独立关联、重复去重、重启清理、多结果不串仪器、视频单在途任务、照片优先、证据限速和读数时延字段。测试不使用 NAS 或真实 GPU，不证明实际面板准确率。当前阿里云账号此前返回 `Arrearage`；账户恢复前不能把视觉兜底视为可用能力。
