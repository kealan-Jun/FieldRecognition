# 工作台推理连接与故障恢复

原工作台仍负责相机、扫码绑定、照片监控、测量草稿及 NAS 归档。独立 GPU OCR 服务通过专用客户端、scope、只读输入根接收工作台的面板区域。它与 AgentDesk 的客户端和存储授权分别配置，不共享业务数据库。

在 OCR 业务进程的私有 EnvironmentFile 中配置 `.env.example` 的 `FIELD_OCR_SERVICE_*`。模型摘要必须与独立服务部署一致；临时输入目录需事先创建，并只读挂载给独立 OCR Worker。凭证文件只供业务进程读取，不返回给网页。远程 HTTP 仅允许 loopback；跨主机必须 HTTPS。

使用该模式时，业务进程设置 `CUDA_VISIBLE_DEVICES=`、`FIELD_PANEL_DEVICE=cpu`。面板定位运行 CPU，PaddleOCR 仍由独立服务使用 GPU；本机不会再加载第二份 GPU 模型。部署启动检查为 `scripts/check_ocr_backend.py --require-remote`。日夜调度计划照常生效；非 OCR 时段保留照片队列，视频推理等待下一个可用时段。

每张业务照片及其区域使用稳定的请求键。断网、超时或响应丢失后复用同一独立任务；不同业务测量即使像素相同也不会合并。返回结果核对区域 SHA-256、模型摘要和真实调用凭证。处理过的传输区域从临时目录移除；原业务照片、原始识别结果及独立任务 ID 保留在回执中。临时目录不是 NAS 归档，不持续保存普通视频帧。

推理服务离线、GPU 时段未到、接入配置异常或排队未完成时，业务任务等待依赖恢复，不耗尽识别失败重试次数。明确输入错误和推理失败仍保留失败状态，不能标记成功。进程被强制终止后通过原队列租约恢复；正常停止时标记的未完成照片在启动后恢复，过时的视频任务不会当作新照片补跑。

托管 unit 关闭启动次数限制，退出后每 30 秒重试。相机、OCR 和归档主进程在完成数据库心跳后通知 systemd；120 秒无心跳则由 watchdog 回收。明确执行 `systemctl --user stop` 仍然停用服务；开机启动由 `field-recognition.target` 及用户 linger 配置负责。NAS 故障时队列继续留在本机，归档沿用持久化 outbox 重试，不能删除源材料来清空积压。

归档批次可能因 NAS 读取缓慢持续数分钟。写入、回执校验、导航整理与目录遍历取得实际进展时，主进程最多每 5 秒更新一次心跳和进度；不使用独立心跳线程掩盖卡住的读写。首次运行先报告启动状态，等待完整性校验锁时分次等待，防止正常长任务反复重启。

相机管理进程同时检查每个采集子进程的独立心跳。子进程退出会重新启动；进程仍在但连续 120 秒没有新心跳时，也会回收重启。其他进程的旧心跳不计作该子进程存活，重启等待按单调时钟计算。

核对入口：`/health/ready`、`/api/admin/status`、`/api/state`。网页会区分后台进程不可用与等待 GPU 服务，不再把纯文本错误响应显示成 JSON 语法错误。基础设施不可用不等于成功识别；实际读数仍需对应照片和模型回执。
