# 云端复核误报保护（2026-10-15）

## 行为与依据

并行初读仍由同一张照片同时启动本地 OCR 和既有云端模型。普通有效复核更新同一任务和 Result/Readings；未增加第二次自动云端调用，也未更换提供方、模型、凭据或原始输入像素。

历史样本中，转速区域原图仅 40×31 像素，本地未读出完整数字，云端曾将助手目视参考的 570 读成 510。原符号/数量级冲突检查依赖两路都有有效值，无法拦住这一情况。仅放大原始像素的四次探测也未解决：该样本两次只返回部分数字 5，另一张仍两次返回 15.00；放大方案未进入生产代码。

修复版本 `8dfee2ebe85f7ded5d19ae4d9edb0d576a16db05`：

- 云端已定位红色数码屏也接受既有原始像素诊断。可测字符组数多于输出数字位数时，不把部分数字作为有效读数；同样不完整的本地候选保留为有质量问题的证据。
- 原图字符高度不足、笔画粘连或小数点不明确时，必须有同字段、同单位的有效本地结果一致支持，才自动应用云端数值。否则保留可用初读、记录 `ambiguous_source_pixels` 或 `incomplete_cloud_readout` 并标记待核对；不根据参考答案补造 570。
- 云端先完成可先给出初步候选，任务继续持有租约并标记 `crosscheck_pending`；本地完成后仍执行符号、数量级及原像素比较，再结束任务。避免先返回者绕过交叉检查。两路始终并行执行。
- 提示词版本为 `panel-readout-v4-complete-fields`，明确同一区域任一位或小数点不确定就整区不可读，不接受只读出首位的解释。

原图、模型原回答、两路候选、冲突依据和不可变归档回执继续保存。质量诊断不是模型置信度，更不是准确率证明；两路一致也可能同错。像素保护目前适用于已定位的红色 LED 区域，其他屏幕及未归属整图沿用既有校验。
